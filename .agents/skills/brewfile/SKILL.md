# Brewfile

Рабочий файл — `~/dotfiles/Brewfile`. Отвечай на языке пользователя.

## Синхронизация Brewfile

Синхронизация означает обновление Brewfile по фактически установленным пакетам Homebrew. Запрос на синхронизацию разрешает обновить этот файл. Не запускай установку, обновление или удаление пакетов, `brew bundle install`, `brew bundle cleanup`, подключение или отключение taps.

1. Прочитай существующий Brewfile и сохрани его точную копию во временном каталоге. Если файл отсутствует, рассматривай результат как создание нового Brewfile; если отсутствует каталог `~/dotfiles`, сообщи об этом, не подменяя путь.
2. Создай новый дамп в отдельном временном файле:

   ```sh
   brew bundle dump --file="$brewfile_tmp_dir/Brewfile.new"
   ```

   Здесь `brewfile_tmp_dir` — заранее созданный через `mktemp -d` временный каталог. Не делай дамп непосредственно поверх рабочего файла. Проверь успешное завершение команды до дальнейших действий. Используй поддерживаемые локальной версией параметры (`brew bundle dump --help`); не добавляй `--install`.
3. Сравни сохранённый старый файл с новым через `diff -u`. Код возврата 1 означает найденные различия, а не ошибку. Отдели добавление и удаление записей от изменений комментариев, порядка и параметров. Дамп — снимок, который может не сохранять ручные комментарии, условия и другие Ruby-конструкции. Если старый файл содержит такую логику, сохрани её и согласуй обновление записей с ней; не исполняй Brewfile ради разбора.
4. Для каждой добавленной или удалённой formula/cask дай краткое описание назначения, для tap — назначение репозитория. Для изменений параметров существующей записи объясни, что изменилось. Получай сведения из `brew info --formula <name>`, `brew info --cask <name>` и `brew tap-info <tap>` либо их JSON-вывода. Сохраняй полные имена из сторонних taps. Если сведения об удалённом пакете недоступны, явно отметь это, не угадывай назначение.
5. Убедись, что рабочий Brewfile не изменился после сохранения копии, и запиши подготовленный результат в `~/dotfiles/Brewfile`. При параллельных изменениях перечитай файл и пересчитай дифф, сохраняя чужие правки. Если пользователь просил только просмотр или дифф, файл не записывай.
6. Покажи итоговый дифф между исходным и записанным файлом и пояснения: действие, тип, имя, назначение. Для большого диффа допустима сводка с путём к полному диффу. Если изменений нет, сообщи об этом и не переписывай файл. Не создавай коммит без запроса.

Не называй дамп полным списком всех транзитивных зависимостей: состав записей определяется Homebrew Bundle. Если нужен полный инвентарь установленных пакетов, используй отдельный сценарий ниже. Учитывай дополнительные типы записей, которые выдаёт локальная версия Bundle; не представляй приложения Mac App Store или расширения редактора как formulae/casks.

## Описание установленных пакетов и репозиториев

Этот сценарий доступен независимо от синхронизации и не изменяет Brewfile.

- Для полного инвентаря используй `brew info --json=v2 --installed`, для подключённых репозиториев — `brew tap-info --installed --json`. При необходимости сверяй списки через `brew list --formula`, `brew list --cask` и `brew tap`.
- Если пользователь назвал конкретные пакеты или репозитории, ограничь описание ими и проверь, установлены ли они. Если запрос относится к записям Brewfile, читай `~/dotfiles/Brewfile` и отдельно отмечай записи, отсутствующие в текущей установке.
- Для formulae и casks показывай имя, тип и краткое назначение. Версию, домашнюю страницу и статус прямой установки/зависимости добавляй, когда это нужно пользователю и подтверждено метаданными Homebrew.
- Для taps показывай имя, URL репозитория и его назначение. Не придумывай описание по одному имени: если метаданных недостаточно, обратись к README репозитория и укажи источник либо отметь отсутствие сведений.
- Группируй результат по formulae, casks и taps. Большой список представляй компактными таблицами, сохраняя полный охват запрошенного набора.
